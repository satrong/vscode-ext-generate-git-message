你需要根据「代码变更内容」，生成一条**规范、清晰、可读性强**的 Git commit message。

请严格遵循以下规则：

---

# 一、输出格式（强约束）

<type>(<scope>): <subject>

<body>

---

# 二、type（必须，且只能使用以下之一）

feat | fix | docs | style | refactor | perf | test | build | ci | chore | revert

---

# 三、scope（必须）

用于标识影响范围，必须从变更内容中提取，优先级如下：

1. 模块（user / auth / api 等）
2. 页面（home / dashboard 等）
3. 技术点（router / webpack / eslint 等）

要求：

* 必须填写，不允许省略
* 使用**单一最核心范围**（不要多个 scope）

---

# 四、subject（必须）

要求：

* 使用「动词 + 宾语」结构（如：新增登录校验、修复接口异常）
* 不超过 50 字
* 不使用句号或结尾标点
* 使用中文
* 必须具体明确，禁止模糊表达（如：优化代码、修改问题）

动词建议（优先使用）：
新增 / 修复 / 优化 / 重构 / 移除 / 支持 / 调整 / 改进 / 限制 / 统一

---

# 五、body（可选，但推荐）

用于说明“为什么这样改”，而不是简单重复 subject。

要求：

* 使用 `- ` 开头列举
* 每行不超过 72 字
* 聚焦：

  * 改动原因
  * 影响范围
  * 关键设计决策

---

# 六、生成策略（关键约束）

当信息不完整时，必须遵循：

1. **优先保证 type 和 scope 准确**
2. subject 基于上下文做合理补全（不得空泛）
3. 不编造不存在的技术细节
4. 不输出不确定语气（如：可能、也许）

---

# 七、强约束规则（必须遵守）

* 只输出最终 commit message
* 不输出解释、分析或多余内容
* 不使用代码块标记（```）
* 不输出多条 commit
* 每行不超过 72 字
* 必须体现明确的改动意图
* UI 改动必须包含页面名称
* 接口改动必须包含接口或服务名
* 性能优化必须说明优化点（如：减少请求次数、降低重绘）

---

# 八、示例

feat(auth): 支持微信登录

* 解决第三方登录流程缺失问题
* 减少用户注册流程复杂度

---
